# Roadmap do portfólio Oakdev

Este documento registra melhorias futuras para retomar o projeto sem perder contexto.

## Estado atual

- landing page enxuta publicada no GitHub Pages
- Laravel como fonte principal para evolução
- `docs/index.html` como versão estática pública
- posicionamento amplo para produtos digitais, serviços, automação, IA e integrações
- casos confidenciais descritos sem expor clientes ou dados
- prévia com dados fictícios disponível somente no ambiente local
- SEO, acessibilidade básica e navegação mobile implementados

## Próximas melhorias

### Conteúdo real

- [ ] adicionar cases reais conforme houver autorização para publicação
- [ ] registrar cada case com contexto, problema, solução, mudança e resultado comprovado
- [ ] substituir exemplos genéricos por experiências verificáveis
- [ ] revisar textos comerciais depois dos primeiros contatos recebidos

### Conversão

- [ ] criar formulário de briefing para novos projetos
- [ ] definir fluxo de solicitação de orçamento
- [ ] adicionar perguntas iniciais para identificar objetivo, público, prazo e escopo
- [ ] configurar mensagem de confirmação após o envio

### Plataforma

- [ ] avaliar domínio próprio
- [ ] avaliar analytics com respeito à privacidade
- [ ] criar CMS somente quando houver conteúdo real para administrar
- [ ] adicionar painel protegido para projetos, serviços e artigos
- [ ] automatizar a sincronização entre Laravel e `docs/`

### Conteúdo e autoridade

- [ ] criar artigos ou notas técnicas quando houver temas relevantes
- [ ] publicar demonstrações reais sem expor código confidencial
- [ ] adicionar depoimentos somente com autorização
- [ ] adicionar métricas públicas somente quando comprovadas

## Regras para futuras alterações

- não publicar dados fictícios, clientes ou resultados inventados
- manter a logística como uma experiência, não como o posicionamento inteiro
- preservar a comunicação ampla para diferentes segmentos
- evitar adicionar seções sem uma necessidade concreta
- revisar a versão Laravel e `docs/index.html` juntas quando houver mudança visual
- usar a skill `clareza-de-negocio` para textos voltados a clientes

## Critério para retomar

Antes de iniciar uma nova melhoria, verificar:

1. qual problema real ela resolve;
2. se há conteúdo ou dados suficientes para sustentá-la;
3. se pertence ao Laravel, à versão pública ou aos dois;
4. se a mudança deixa a página mais clara ou apenas mais cheia.
